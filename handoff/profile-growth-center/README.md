# EasyRef Personal Growth Center Handoff

这个目录是给比赛强制使用的 AI 的独立交接包。目标是让它完成一个展示感强、风险较低、不会破坏核心论文工作流的功能：把现有个人中心升级为「学术成长中心」。

注意：这个功能必须真实接入后端数据。可以保留空状态和接口失败 fallback，但不能只做静态 mock 页面。

## 任务定位

把当前简陋的个人中心升级为用户的数据中心，覆盖：

- Token 使用统计：为后续收费、套餐、额度控制做准备。
- 成就徽章系统：用论文阅读、AI 提问、总结、引用生成等行为驱动留存。
- 年度学术总结：生成可展示、可分享的年度研究报告。
- 研究画像：展示用户的论文阅读轨迹、关键词、活跃度。
- 账户权益中心：预留免费版 / Pro / Pro Plus 的商业化入口。

## 明确边界

这个任务应该尽量只动个人中心相关代码，不要改动核心论文功能。

允许：

- 重构或替换现有 `ProfilePage`。
- 新增个人中心子组件。
- 新增后端聚合接口。
- 接口失败时可以使用空状态 fallback。
- 新增与使用量、徽章、年度报告相关的数据表。
- 新增必要 CSS 和 i18n 文案。

禁止：

- 不要改论文解析、PDF 阅读器、RAG 问答、引用生成的核心逻辑。
- 不要改登录、注册、Supabase 鉴权的主流程。
- 不要引入重型图表库，除非项目已经有依赖或确有必要。
- 不要删除现有头像上传、修改密码能力。
- 不要把真实支付逻辑接进来，套餐页只做预留入口。

## 推荐实现策略

第一阶段先做「真实接口最小版本」：

1. 保留头像、邮箱、修改密码。
2. 新增个人中心 tab：概览、Token、成就、年度报告、权益。
3. 新增 `/api/user-growth/summary` 或同等接口。
4. 从真实数据库聚合论文数、AI 调用、token 使用、徽章进度。
5. 页面视觉完成度优先，核心业务零侵入。

第二阶段增强统计准确性：

1. 在后端记录 AI 调用 token。
2. 聚合每日使用量。
3. 根据统计自动解锁徽章。
4. 根据年度数据生成报告。
