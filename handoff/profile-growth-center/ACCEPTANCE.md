# Acceptance Criteria

完成后按这个清单验收。

## 必须完成

- [ ] 个人中心不再只是头像和密码，已经升级为「学术成长中心」。
- [ ] 页面至少包含：概览、Token 统计、成就徽章、年度报告、账户权益、设置。
- [ ] 前端个人中心代码位于 `frontend/src/components/profile/`，不要重新塞回 `Pages.jsx`。
- [ ] 原有头像上传能力没有被删除。
- [ ] 原有修改密码能力没有被删除。
- [ ] 未登录 / local 用户场景下页面不崩溃。
- [ ] Token 页面能展示今日、本月、总计、剩余额度。
- [ ] Token 页面能展示趋势、功能占比、最近调用记录。
- [ ] Token、徽章、年度报告数据来自真实后端接口，不是静态 mock。
- [ ] 成就页面至少有 10 个徽章，并显示进度。
- [ ] 年度报告能展示年度摘要和研究人格。
- [ ] 权益页能展示 Free / Pro / Pro Plus 三档或等价套餐。
- [ ] 页面在桌面和移动端都没有明显重叠、溢出、文字挤压。
- [ ] 新增文案有中文和英文。
- [ ] `frontend` 目录下 `npm run build` 可以通过。

## 不应出现

- [ ] 不应破坏论文库列表。
- [ ] 不应破坏 PDF 阅读器。
- [ ] 不应破坏论文聊天和 RAG 问答。
- [ ] 不应破坏引用生成。
- [ ] 不应强制用户登录才能看个人中心的基础展示。
- [ ] 不应引入没有使用的大型依赖。
- [ ] 不应出现只有 mock 的静态展示。

## 体验标准

- [ ] 用户一眼能看到本月 token 已用多少。
- [ ] 用户能知道哪些功能最耗 token。
- [ ] 用户能看到自己离下一个徽章还差多少。
- [ ] 年度报告有展示感，适合比赛演示。
- [ ] 套餐权益让后续收费方向清楚，但不需要真的支付。

## 推荐验收命令

```bash
cd frontend
npm run build
```

如果新增了后端接口，也要启动后端并手动访问接口，确认空用户、local 用户、真实邮箱用户都能返回合理数据。
